## 什么才算文字区域

文字区域是已经落在某个界面容器里的阅读内容，不包括容器本身：

- 公告类型与日期：低权重元信息。
- 正文分区标题：告诉读者接下来谈哪类内容。
- 条目引导词：短、粗体，通常在冒号前结束。
- 条目解释：常规字重，允许多行连续阅读。
- 次级条目：以 `○` 继续拆分，不另造卡片。
- 备注：以 `※` 标记条件、例外或风险。
- 行内强调：只加粗关键结论、数字或功能名，不整段变色。

不算文字区域的内容：

- 官网的全局导航、背景和页脚。
- 公告页面最上方的版本主标题。
- 版本前瞻视频的章节卡、字幕和蓝紫宣传说明条。
- 游戏菜单的列表框、选中描边、图片格与按钮；这些属于界面结构证据。

## 官网实测层级

浏览器桌面视口约 `1264px` 宽时：

| 层级 | 官网实测 | 作用 |
| --- | --- | --- |
| 正文列 | `782px`，约视口 `62%` | 保持单一连续阅读列 |
| 公告类型／日期 | `8px` 常规 | 元信息，不抢正文 |
| 页面主标题 | `24px` 常规 | 只标识公告，不用于主题母版 |
| 研发通讯正文分区 | `26px / 700` | 大段内容的章节边界 |
| 更新说明一级分区 | `19.5px / 700`，常带 `▼//` | 更新日志的大类边界 |
| 更新说明二级分区 | `15.21px / 700`，常带 `■` | 具体系统分类 |
| 正文 | `13px / 400` | 连续说明 |
| 条目短标题／关键结论 | `13px / 700` | 与正文同字号，仅靠字重分层 |

比例比绝对像素更重要：研发通讯分区标题约为正文的 `2×`；条目短标题不放大，只加粗。

## 研发通讯的稳定句法

```text
交互与易用性优化

· 任务与标记追踪优化：在【任务】界面点击【开始追踪】后……
· 帝江号体验优化：
  ○ 连续拜访好友的帝江号时，加载速度将加快。
  ○ 舱室升级可通过【总控中枢】远程操作。
※ 条件、期限或例外说明。
```

可观察规则：

1. `·` 条目不包独立卡片，依靠段间距和粗体短标题分组。
2. 冒号前是扫描锚点，冒号后才是解释正文。
3. 次级信息继续使用 `○`，不再提升字号。
4. 方括号 `【】` 标记明确的游戏功能名；不能把普通名词全部括起来。
5. 行内粗体只强调结论和数值，例如“上限由200米提升至300米”。

## 与游戏内样本的组合边界

- `ACTUAL_UI_CLUE_LIST.md` 决定左侧列表、选中态、详情条、按钮与背景关系。
- 本文决定右侧阅读内容内部的标题、条目、解释、次级条目和备注。
- 两种证据不能互换：公告文字不能决定面板形状，游戏列表也不能决定长正文的段落句法。
