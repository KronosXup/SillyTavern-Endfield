## 视频包装与游戏 UI 的边界

![宣传文字层对照](reference/promo-layer/promo-layer-board.png)

跨越不同功能画面后仍保持一致的左下说明组件，属于版本前瞻的视频后期包装：

- 大标题、斜向连接符和细长水平线组成第一层。
- 一至两行功能说明组成第二层，并落在蓝紫渐变的局部底条上。
- 组件宽度由文字决定，不扩张为整页面板。
- 深色、浅色和高密度背景下仍保持相同锚点与阅读顺序。
- 背景功能页面继续可见；文字层没有把场景改造成另一种布局。

`系统优化前瞻` 等大章节标题卡同样属于节目转场。两者可以辅助判断视频剪辑的进入节奏，但不能据此推导游戏内面板、文字层级或 SillyTavern 主题骨架。先前的 `promo-package-v1` 因此标记为废弃路线。

新的取证单位必须是**一个实际游戏内功能界面**。同一轮只分析该界面内部的标题、正文、导航、列表、选中态和状态切换；不把节目包装、字幕或其他功能页混入。

## 动态事实

本地逐帧表：

- `reference/frames/motion-section-overlay.png`
- `reference/frames/motion-confirmation-band.png`
- `reference/frames/motion-reward-strip.png`

在每秒 2 帧的采样中可以确认：

1. 功能标题是在场景切入后作为独立的左下信息层出现，而不是先铺一个全屏面板。5 fps 补采样进一步确认了“青色结饰 → 标题揭示 → 菱形接线 → 蓝紫要点板 → 两行文字”的分段进入顺序。
2. 确认状态同时改变背景清晰度并加入横向白带；关闭后恢复原界面。采样不足以判断精确 easing，不应臆造弹簧或漂浮动画。
3. 奖励页会暂时收走复杂详情，将视觉焦点压缩成中央单行物品，再返回功能界面。

## 设计结论

终末地界面的统一性不来自单一深色配色，而来自以下规则：

- 场景、角色或功能内容先占据主画面，UI 再依附边缘。
- 深色场景页与浅色工作页并存，但都使用连续画布，而非卡片墙。
- 黄色承担当前选择、主操作和方向性构图，不能平均撒在所有控件上。
- 弹窗、奖励和章节提示各有不同的画面重组方式，不能只换容器颜色。
- 动画首先服务于焦点转移：场景到信息层、界面到确认带、详情到奖励条。

## 功能页面的使用边界

| 功能样本 | 允许影响的 SillyTavern 部位 | 当前是否进入概念图 |
| --- | --- | --- |
| 前瞻节目文字包装 | 仅可记录剪辑节奏，不映射 ST | 否，已排除 |
| 连续任务行 | 最近聊天列表 | 否，单独设计欢迎页时再用 |
| 浅灰篆刻工作面 | 设置／世界书等高密度抽屉 | 否 |
| 角色栅格与详情 | 角色管理 | 否 |
| 横向确认带 | 删除、覆盖等确认弹窗 | 否 |
| 奖励条 | 完成状态或快捷动作反馈 | 否 |
| 工业规划 HUD | 背景层和边缘工具 | 否，需另外验证可读性 |

## 明确废弃

- 废弃“全局黑底 + 白色列表 + 黄色按钮”作为主概念。
- 废弃 `SESSION ARCHIVE` 等没有来源的伪设定文字。
- 废弃用终末地常见颜色代替布局和状态设计的做法。
- 废弃从剧情字幕、人物台词或对话框反推聊天界面的做法。
- 当前 `Protocol β0.2` 只保留为失败对照，不作为下一版的样式基础。
